## 역할을 먼저 이름 짓기

구현 색상이나 화면 위치보다 사용자의 목적과 UI 역할을 이름에 담습니다. 같은 역할은 테마가
바뀌어도 같은 semantic token과 컴포넌트 API를 사용해야 합니다.

## 기본값은 안전하게

기본 variant, button type, focus 표시처럼 자주 빠지는 결정을 컴포넌트가 안전하게 제공합니다.
소비자는 제품 의미에 필요한 옵션만 지정합니다.

## 의존성은 드러내기

스타일 로딩과 테마 선택은 애플리케이션이 명시적으로 결정합니다. 숨은 전역 주입이나 React
중복 번들을 만들지 않습니다.

## 문서의 역할을 분리하기

개념과 사용 지침은 Starlight에, 상태·variant·controls·interaction은 Storybook에 둡니다.
두 곳에 같은 설명을 복제하지 않고 서로 연결합니다.
