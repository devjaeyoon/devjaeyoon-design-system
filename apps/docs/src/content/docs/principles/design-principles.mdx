## 역할을 먼저 이름 짓기

구현 색상이나 화면 위치보다 사용자의 목적과 UI 역할을 이름에 담습니다. 같은 역할은 테마가
바뀌어도 같은 semantic token과 컴포넌트 API를 사용해야 합니다.

의미를 나타내는 옵션과 시각적 표현을 선택하는 옵션은 구분합니다. Button의 행동 이름은
“저장”·“삭제”처럼 작업을 설명하고, `tone`은 위험 여부 같은 의미를, `variant`는 강조 수준과
표현 방식을, `size`는 크기를 선택합니다. 표현 방식에는 `outline`·`ghost` 같은 이름을 사용할
수 있습니다. 위험한 행동의 의미는 variant와 별개로 `tone="danger"`로 전달합니다.

## 기본값은 안전하게

기본 variant, button type, focus 표시처럼 자주 빠지는 결정을 컴포넌트가 안전하게 제공합니다.
소비자는 제품 의미에 필요한 옵션만 지정합니다.

## 의존성은 드러내기

스타일 로딩과 테마 선택은 애플리케이션이 명시적으로 결정합니다. 숨은 전역 주입이나 React
중복 번들을 만들지 않습니다.

## 문서의 역할을 분리하기

| 위치 | 책임 |
| --- | --- |
| Starlight 원칙 문서 | 모든 컴포넌트에 적용하는 기준과 이유 |
| Starlight 컴포넌트 문서 | 선택 기준, 기본값, 상태별 동작을 포함한 API 계약과 소비자의 책임 |
| Storybook | 상태·variant의 시각적 조합, controls, 상태 전환·키보드 조작 예제와 자동 검증 |

Starlight에는 올바른 사용에 필요한 계약 설명과 최소 사용 예제를 둡니다. 예를 들어 “loading
중에는 실행할 수 없다”는 Button의 사용 계약입니다. 실제 loading 전환 예제와 중복 실행 방지
검증은 Storybook에 둡니다. 전체 상태 갤러리와 상호작용 예제는 중복 구현하지 않고 연결합니다.
